# Нативная проверка на устройстве пользователя — НЕ ВЫПОЛНЕНА

Проверять только синтетический набор. Тестовый crypto bridge не включать.

1. Открыть готовый `index.html` в доверенном локальном режиме или с HTTPS / loopback. Зафиксировать ОС, браузер и версию. Проверить доступность native `crypto.subtle` без подстановок.
2. Открыть «Защита», выбрать произвольные фильтры и сохранить файл с новым учебным паролем. Убедиться, что сохранён именно `.fcvault`, а не CSV.
3. Повторить сохранение. Убедиться, что файлы различны, затем открыть оба. Показатели и настройки должны восстановиться.
4. Закрыть вкладку, открыть чистую новую, загрузить файл и ввести пароль. Не должно требоваться никакой серверной сессии.
5. Ввести неверный пароль. Не должно быть восстановления, подмены цифр или автоматической открытой выгрузки.
6. Изменить один символ ciphertext в тестовой копии. Открытие должно завершиться отказом. Не менять оригинальную копию.
7. Проверить Escape/отмену во время обработки и повторный submit: не должно быть поздней/дублированной выгрузки.
8. Проверить CSV-экспорт: предупреждение обязательно; отмена не создаёт файл.
9. В Network убедиться, что после первоначальной загрузки HTML операции не отправляют данные в сеть. Повторить сценарий в офлайн-режиме.
10. Повторить в другом поддерживаемом браузере и на физическом телефоне. Если Web Crypto недоступен, получить явный отказ, а не fallback.

Записать результат каждого пункта, артефакт сборки (SHA-256) и фактическую среду. Проверка одного браузера не означает поддержку всех браузеров. Даже полный PASS этого списка не равен независимому аудиту безопасности.
